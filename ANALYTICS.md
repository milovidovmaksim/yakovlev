# Аналитика сайта

Система целиком живёт в этом репозитории и на GitHub Pages. Никаких кабинетов
Plausible, Umami или Cloudflare и никаких платежей: Метрика выступает только
сборщиком данных, всё остальное — своё.

## Как это устроено

1. `assets/js/analytics.js` — счётчик Яндекс.Метрики и цель `max_click` (клик по
   любой ссылке с `max.ru`). Подключён во всех пяти страницах сайта.
2. `.github/workflows/stats.yml` — раз в час запускает `scripts/fetch-stats.mjs`.
   Скрипт берёт из API Метрики агрегаты по дням, шифрует их ключом `STATS_KEY`
   и коммитит в `assets/data/stats.json`.
3. `statistika.html` — страница с двумя крупными цифрами. Читает зашифрованный
   файл и расшифровывает его ключом из ссылки (`#k=...`). Ключ не отправляется
   на сервер: всё происходит в браузере.

Токен Метрики и ключ шифрования хранятся только в секретах GitHub Actions.
В репозитории (даже публичном) их нет, а данные лежат зашифрованными.

## Настройка (один раз)

### 1. Счётчик и цель в Метрике

1. Создайте счётчик на [metrika.yandex.ru](https://metrika.yandex.ru). В поле
   «Адрес сайта» укажите новый домен; данные собираются с любого домена, где
   стоит код счётчика, так что переезд ничего не сломает.
2. Впишите номер счётчика в `assets/js/analytics.js`:

   ```js
   var COUNTER_ID = 0; // было
   var COUNTER_ID = 12345678; // стало
   ```

3. Создайте цель: **Настройка → Цели → Добавить цель**.
   - тип: **JavaScript-событие**;
   - идентификатор: `max_click`;
   - название: «Клик «Написать в Max»».

   Если назовёте иначе — идентификатор всё равно должен быть `max_click`.

### 2. Токен для API Метрики

1. Откройте [oauth.yandex.ru/client/new](https://oauth.yandex.ru/client/new) и
   создайте приложение.
   - Платформа: **Веб-сервисы**.
   - Redirect URI: `https://oauth.yandex.ru/verification_code`.
   - Доступ к данным: **Яндекс Метрика** → «Получение статистики, чтение
     параметров своих и доверенных счётчиков» (`metrika:read`).
2. Сохраните приложение и скопируйте **ClientID**.
3. Откройте в браузере:

   ```
   https://oauth.yandex.ru/authorize?response_type=token&client_id=<CLIENT_ID>
   ```

   Разрешите доступ. В адресной строке появится `access_token=...` — это и есть
   токен. Он долгоживущий, менять его не нужно.

### 3. Секреты репозитория

В GitHub: **Settings → Secrets and variables → Actions → New repository secret**.

| Имя | Значение |
| --- | --- |
| `METRIKA_TOKEN` | токен из шага 2 |
| `METRIKA_COUNTER_ID` | номер счётчика, только цифры |
| `STATS_KEY` | пароль для шифрования и для ссылки, 40+ случайных символов |

Ключ можно сгенерировать в PowerShell:

```powershell
[guid]::NewGuid().ToString('N') + [guid]::NewGuid().ToString('N')
```

Там же включите запись для Actions: **Settings → Actions → General →
Workflow permissions → Read and write permissions**.

### 4. Первый запуск

**Actions → «Статистика сайта» → Run workflow**. Через минуту в репозитории
должен появиться `assets/data/stats.json` (зашифрованный). Дальше всё идёт само
раз в час.

### 5. Ссылка для собственника

```
https://<домен>/statistika.html#k=<STATS_KEY>
```

Например, если ключ `a1b2...`, ссылка будет
`https://yakovlev.ru/statistika.html#k=a1b2...`. Откройте её один раз, проверьте
цифры и сохраните в закладки или менеджер паролей. Ссылку можно открывать с
телефона и добавить на главный экран — она выглядит как обычный сайт.

## Что видит собственник

- Две крупные цифры: **посетители сайта** (уникальные) и **нажали «Написать в
  Max»**, плюс процент нажавших.
- Переключатель «Сегодня / 7 дней / 30 дней» и график по дням.
- Подпись «Данные на …» — время последнего сбора.
- Ничего вводить и логинить не нужно. Без ссылки страница показывает только
  «Страница доступна по персональной ссылке».

## Ограничения

- GitHub Pages — статический хостинг, он не может принимать и записывать
  данные. Поэтому сборщик — Метрика. Полностью свой учёт без единого внешнего
  сервиса потребовал бы собственный сервер или базу.
- Обновление раз в час, GitHub может задержать запуск на 10–30 минут. Оперативных
  данных «прямо сейчас» на странице нет — для этого есть сама Метрика.
- Часовой пояс расчёта — `Asia/Yekaterinburg`. Меняется переменной
  `STATS_TIMEZONE` в `stats.yml`.
- Хранятся только агрегаты по дням, без IP, cookie и других персональных данных.
  Уведомление о cookie всё равно нужно из-за счётчика Метрики.
- Репозиторий публичный — данные зашифрованы, но ключ должен быть длинным и
  случайным. Если ссылка «утекла», поменяйте секрет `STATS_KEY`, запустите
  workflow вручную и раздайте новую ссылку: старая перестанет работать.
- Если Pages настроен как «Deploy from a branch», коммит бота обновляет сайт сам.
  Если деплой идёт через отдельный GitHub Actions workflow — добавьте деплой в
  конец `stats.yml`.

## Если что-то не работает

- **Workflow красный, ошибка 403** — у токена нет доступа `metrika:read`,
  перевыпустите токен или проверьте секрет `METRIKA_TOKEN`.
- **«Данных пока нет»** — workflow ещё не запускался, либо Pages не пересобрал
  сайт после коммита бота.
- **«Ссылка не подходит»** — ключ в ссылке не совпадает с `STATS_KEY` или ссылка
  скопирована не целиком (важна часть после `#`).
- **Клики показываются как «—»** — цель `max_click` не создана или у неё другой
  идентификатор. Проверьте в Метрике; при необходимости задайте `GOAL_ID`
  в `stats.yml`.
- Локальная проверка страницы: запустите `python -m http.server` в папке сайта и
  откройте `http://localhost:8000/statistika.html#k=<ключ>`. С `file://` страница
  не расшифрует данные — браузер не даёт доступ к криптографии.
